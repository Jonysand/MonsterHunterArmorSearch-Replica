# mhwilds.wiki-db.com/sim 实现方式调研报告

调研对象：https://mhwilds.wiki-db.com/sim/ （MH Wilds スキルシミュ(泣)，wiki-db.com 系列）
调研方式：前端资源下载 + Closure 混淆 bundle 静态分析 + 原站浏览器行为实测（只读，无攻击性操作）
日期：2026-09-29

## 1. 总体架构

- **后端**：Django（表单 csrfmiddlewaretoken、语言切换 /i18n/setlang/）
- **前端**：纯静态单文件应用 —— Google Closure Compiler（ADVANCED_OPTIMIZATIONS）编译的
  **Preact** 应用，`bzlcompiled/sim-compiled-<lang>.js.es6.js`（Bazel 构建，按语言出包：
  ja/en/ko/zh-hans/zh-hant，数据与 UI 文案编译进 bundle）
- **游戏数据**：全部内嵌于 JS bundle（约 300KB/语言），无运行时数据请求
- **持久化**：localStorage（protobuf 编码的护石/所持数/搜索配置，键如 `mhwilds-zh-hans-deco`）
- **分享**：URL hash（`#skills=弱点特效Lv3&s=1&e=1&w=LV3-1-1&d=0&rf=-100...&l=200`）+
  独立分享页（path 末段为 protobuf base64，经 `renderSavedResultPagePb` 解码）

## 2. 数据模型（全部以紧凑数组内嵌，Closure 混淆名 → 语义）

- **防具主表 `kd`（891 条，含 182 条内置护石）**，14 元组：
  `[name, rarity, type, part, A, C, D, upgradeGroup, I, slotCount, slots, skills, defense, resists]`
  - part：0头 1身 2腕 3腰 4脚 5护石；type/rarity 恒为 3；A/C/D/I 恒为 0（旧作遗留字段）
  - slots = 插槽**等级**列表（降序、0 补齐 3 位，如 [3,1,0] = 一个Lv3 + 一个Lv1）
  - defense（实测 0~82）；resists = [火,水,雷,冰,龙]
  - upgradeGroup 5/6 的防具在运行时生成 "+" 变体：每档插槽等级 +1（封顶 3；组 6 只升前两档）
- **防具珠 `Ud.Aa`（69 条）/ 武器珠 `Ud.ca`（295 条，含 173 复合珠）**，6 元组：
  `[name, 1, slotLv, 0, 0, skills]`
- **武器技能集合 `Vd.Ea`（51 技能）**：与武器珠技能并集**完全相等** —— 武器系技能只能靠武器珠
- **技能分组 `Vd.kb`（11 组）**：`[组名, [[条目名, 基础技能, 等级, 3], ...]]`，用于选择器
- **技能权重 `Ud.lb`**：全部为 1（Wilds 版未启用差异化权重，剪枝按 1:1 计）
- 部位索引另有 6=武器（虚拟部位，武器插槽由用户输入）

## 3. 核心算法

### 3.1 候选构建（`ne.D`）
- 提供任一**需求技能**的防具全部保留；不提供者按「部位 + 插槽档数」分桶、桶内按槽位模式再分组，
  仅保留防御最高者（被支配装备剔除）；固定/除外装备在此处理
- 成本 `cost = Σ需求技能提供等级 + 插槽数`，候选按成本**降序**排序

### 3.2 主搜索（`Ne.D`，MHWilds 子类 `Dh`）
- 六部位（含护石）分支限界 DFS，生成器实现、200ms 分批让出主线程、增量上报结果与进度
- **剪枝**：`候选成本 × 空部位数 + 已装配插槽总数(hd) < 技能差额加权分(Ge) → break`
  （候选已按成本降序，后续更差）；另有访问栈支配去重（同部位、插槽逐档 ≥、需求技能提供 ≥）
- **完成判定**：`差额 ≤ 已装配槽数` 时尝试用防具珠一次性补齐全部差额（`Sd` 单技能防具珠 +
  所持数校验 + 桶级联），成功即记录解**并提前返回**（不再向深搜索）
- **武器技能**：从需求集中剥离（`S`），在武器插槽模式层先做 `Ch → Ng` 可行性检查 ——
  武器珠只能放入武器插槽，防具提供的武器技能可抵扣
- 防具珠不可入武器插槽、武器珠不可入防具插槽：两套桶独立

### 3.3 装饰品求解（`Mg/Og/Pg`）
- 桶模型：`buckets[1..3]` 按等级计数；放珠 `buckets[珠级] -= n`；级联容量
  `Kg = b3 + min(0, b2 + min(0, b1)) < 0 → 回滚`（Lv1 珠可溢出占用高级桶，反向不行）
- 单技能珠贪心 + 复合珠回溯；所持数约束（默认 100/无限）

### 3.4 追加技能检索（`Gh`）
- 对每个未满级技能：需求 +1 → 跑 limit=1 的完整搜索 → 有解即可追加；100ms 分批 + 进度条

## 4. UI 结构（zh-hans 文案内嵌 `Qe()` 字典，124 键）

- 四标签：搜索 / 我的套装 / 护石 / 装备设定
- 搜索页：武器插槽下拉（20 模式）→ Group Skill/系列技能下拉 → 结果数/最低防御/五属耐 →
  分组技能选择器（每技能一个 Lv 下拉）→ 搜索/追加技能检索/重置
- 结果行含部位（可显示"无"）、防具珠、武器珠布置

## 5. 实测确认（浏览器）

- hash 参数与 `dh()` 解析一致；`skills=` 以「技能名LvN」逗号分隔
- 弱点特效 Lv3 搜索 → 结果含护石（痛击护石Ⅲ）与防具珠（痛击珠【3】）两种补齐方式
- 结果允许空部位（i18n `armorset-eq-none: 无`；分享格式亦允许空部位）

候选合并、成本排序剪枝、桶级联珠求解、武器珠独立桶、追加技能检索、hash 互通；
